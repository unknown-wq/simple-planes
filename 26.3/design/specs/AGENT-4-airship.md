# AGENT-4: the airship and the mini helicopter (Minecraft 26.3 line)

Two aircraft, both in the plane family with their own force model. **Part A**: the airship's flight
model: buoyancy and ballast, a fly-by-wire altitude hold, slow heavy turning, and its ground handling.
**Part B**: the mini helicopter, a subclass of the existing helicopter with smaller, sharper numbers, one
seat and a service ceiling. For both, the entity stubs, items, models, renderers (livery switch, envelope,
culling box, control surfaces), registration and the headless test command already exist on your base
branch (foundation agent); you replace the flight models and prove the numbers on your own server.
Design: `26.3/design/DESIGN.md` (§1.4, §5, §5b, §8.3, §11.2, §11.4); plan: `26.3/design/PLAN.md`; read
`26.3/design/reports/AGENT-1-REPORT.md` first, and `HelicopterEntity.java` (its header explains the tick
order and the sign conventions; the foundation turned its constants into getters you override in Part B).
Do Part A first; Part B is small.

## Part A: the airship

### Controls (unchanged inputs, new meaning)

| input | synched field | meaning on the airship |
|---|---|---|
| throttle 0..5 (arrows up/down) | `THROTTLE` | engine thrust along the hull axis |
| W / S | `PITCH_UP` (+1 / -1) | elevator: commands a vertical speed of +-0.12 b/t; released = altitude hold |
| arrows left / right | `YAW_RIGHT` | rudder: a yaw-rate command (sign), ramped |
| A / D (`moveStrafing`) | none | ignored |
| Space | `MoveHeliUpPacket` | does not reach this class; ignored |

Booster refused (`acceptsUpgrade`). No autopilot type.

### State (new, in `AirshipEntity`)

`double trim` in [-1, +1] (-1 all ballast dumped, +1 full), `double trimInt` (integrator), `double holdY`
(captured altitude), `float yawSpeed` (inherited field), `float hullPitch` (use `xRot`). Persist
`trim`, `trim_int`, `hold_y`, `throttle` (like the helicopter: an airship reloaded with its ballast
reset would fall or float away) in `addAdditionalSaveData`/`readAdditionalSaveData`, clamped on read;
strip them from the item as `HelicopterEntity.getItemStack` does for its controls.

### Force model, per tick (mass normalised; every term is an acceleration in b/t^2)

```
G = 0.03 (tempMotionVars.gravity; keep reading it so isNoGravity() works)
riders        = getPassengers().size()
static        = -0.006 * trim - 0.0006 * riders                       (buoyancy minus weight, at neutral 0)
push          = 0.004 * getThrottle()   (pushPerNotch 0.004f)          along (yaw, xRot); 0 when !isPowered()
vh            = horizontal speed
hDrag         = 0.025 vh^2 + 0.004 vh + 0.0002                        (applied to the horizontal vector)
vDrag         = (0.05 |vy| + 0.02) * vy
lift          = 0.06 * vh^2 * toRadians(xRot)                          (vertical, from hull incidence)
heading align : the horizontal velocity heading is pulled toward yRot by 0.03 of the difference per tick
                (lerpAngle180 so reversing is stable), speed preserved
```

Integration order in `tickMotion` (replacing the plane's): drag, engine, static, lift, gravity is
already inside `static` (buoyancy at neutral cancels it: do not add `gravity` again), then the hard
backstop `|v| <= 1.5`.

### Altitude hold and the elevator (`tickPitch`, replacing the plane's)

```
if (pitchUp != 0)  vsCmd = 0.12 * pitchUp;  holdY = y + 30 * vy       (capture at the predicted stop point)
else               vsCmd = clamp(0.01 * (holdY - y), -0.12, 0.12)
e       = vsCmd - vy
trimInt = clamp(trimInt - 0.10 * e, -1, 1)
want    = clamp(trimInt - 8.0 * e, -1, 1)
trim   += clamp(want - trim, -0.02, 0.02)
xRot   -> approach(10 deg * vsCmd / 0.12, at 0.5 deg/t); 0 when within 1 b of the ground; rotationRoll -> 0
```

Envelope clearance: `holdY` is never allowed below `surface + 9.0` where `surface` is the maximum
`MOTION_BLOCKING` height over the five columns `(0,0)`, `(+-4 along the hull, 0)`, `(0, +-2.5 across)` in
world coordinates (rotate by `yRot`); when the elevator is held down the command is clamped to reach
that floor and no lower unless the ground under the wheel is clear (the five-column surface equals the
surface under the entity), in which case a landing is allowed: the command floor becomes the ground.
Use `combat/Ground.surfaceHeight` for the heights; unloaded columns answer `UNKNOWN` and are ignored.

### Yaw (`tickYaw`) and roll (`tickRoll`)

```
yawSpeed ramps 0.04 deg/t^2 toward 0.6 * sign(yawRight) (0 when yawRight == 0), clamped +-0.6
setYRot(getYRot() + yawSpeed)     (no bank correction; the hull stays level)
rotationRoll = approach(rotationRoll, -0.3 * yawSpeed * 10, 0.2)   (a 1.8 deg lean in a full turn, cosmetic; keep |roll| <= 8)
```

`tickRotateMotion`: only the heading alignment above; no lift; return `q` unchanged.
`tickOnGround`: keep `refreshGroundContact()` and the repair timer; on real contact (`onGround()`) shed
25 % of the horizontal speed per tick (the wheel is a castor), force `xRot` and `rotationRoll` to 0; when
`throttle == 0 && pitchUp == 0` on the ground, move `trim` toward +1 at 0.02/t and set `holdY = y`
(moored). Return `true` so `tickPitch` runs.

`getRotationSpeedMultiplier()`: 0.24, so the inherited `2.5 * mult` idiom would read 0.6 for anyone
who asks; your `tickYaw` uses the constants directly.

## Integration

- `entities/AirshipEntity.java`: the six hook overrides, the state, save/load, `getItemStack` control
  stripping, `getVerticalSpeed()`/`getHorizontalSpeed()` accessors (same names as the helicopter's).
- `client/render/AirshipRenderer.java`: as the foundation left it; only touch it if the envelope or the

  <-1..1>` (sets `trim` and `trimInt`, test aid), `hold <id> <y>` (sets `holdY` with the elevator
  centred), `trace <id> on|off` (one line per tick with the `status` fields, logged at `INFO`, prefix

- The foundation's `/aircraft set <id> throttle|pitch|yaw` writes the synched inputs the airship reads;
  `/aircraft spawn airship x y z` spawns one with a fuelled engine.

## Part B: the mini helicopter

### What it is

A one-seat bubble helicopter, 3.5 b long with a 3.375 b rotor, half the existing helicopter, in a
standard (block material) or medical (white air-ambulance) livery. `MiniHelicopterEntity extends
HelicopterEntity` (stub from the foundation: one `Player` rider, no large upgrades or payload, livery by
the block tag `simpleplanes:mini_heli_medical`, seat from the contract). It flies the helicopter's flight
model; you make it lighter, twitchier, slower and give it a ceiling by overriding the getters the
foundation added to `HelicopterEntity`.

### Getter overrides (in `MiniHelicopterEntity`)

| getter | helicopter default | mini helicopter |
|---|---|---|
| `collectivePerNotch()` | 0.010 | **0.015** (hover at notch 2) |
| `rotorInflowLimit()` | 2.0 | 1.6 |
| `maxCyclic()` | 25 | **30** deg |
| `maxCyclicRate()` | 2.0 | **3.5** deg/t |
| `maxYawRate()` / `yawRamp()` | 3.0 / 0.5 | **4.5 / 1.0** |
| `turnFromBank()` | 2.6 | 3.0 |
| `hDragQuad()` / `hDragLin()` / `hDragConst()` | 0.009 / 0.0025 / 0.0002 | **0.025 / 0.004 / 0.0003** |
| `vDragQuad()` / `vDragLin()` | 0.045 / 0.050 | unchanged |
| `maxSpeedBackstop()` | 2.0 | 1.5 |
| `groundFriction()` | 0.25 | 0.30 |
| `ceilingThrustFactor(y)` | 1.0 | `Mth.clamp(1 - (y - 100) / 100, 0.4, 1)` |
| `getRotationSpeedMultiplier()` | 1.2 | 1.8 (so the inherited `2.5 * mult` idiom reads 4.5) |

Everything else is inherited: turn coordination, velocity alignment, `applyYaw`, the dead-machine
behaviour, the persisted controls, the item that strips them.
