# AGENT-5: the quadcopter crane (Minecraft 26.3 line)

You implement the quadcopter as a flying crane: a small, unmanned, server-flown multirotor that
picks up mobs, animals and players on a rope and hook, carries them and sets them down, directed by a
remote item and by console commands. The entity stub (hovering, synched attitude, rope fields), the
renderer (rope through vanilla's leash renderer, jaws from `carrying`), the items (`quadcopter`, the
`crane_remote` stub), the registration and the `/crane` command stub already exist on your base
branch (foundation agent); you write the physics, the controller, the rope and pendulum, the state
machine, the remote's behaviour and the command, and prove it on your own server. Design:
`26.3/design/DESIGN.md` (§1.2, §1.3, §6, §11.3); plan: `26.3/design/PLAN.md`; read
`26.3/design/reports/AGENT-1-REPORT.md` first.

## Goal

Units: blocks, ticks, degrees; masses in drone masses (the empty drone is 1). All constants below are
the design's; keep them as named constants in the plain classes.

### 1. `entities/crane/MultirotorPhysics` (plain class, no Minecraft imports)

State: position `p`, velocity `v` (both `double[3]`, world axes, y up), yaw `ψ`, tilt angles `θ`
(pitch, nose down positive), `φ` (roll, right down positive), thrust `T`, total mass `m`.

```
G        = 0.04
T_MAX    = 3.0 * G = 0.12
TILT_MAX = 25 deg;  TILT_RATE = 4 deg/t;  TILT_TAU = 2 t   (attitude follows the command: step = (cmd - now)/TAU, clamped +-TILT_RATE)
YAW_RATE_MAX = 6 deg/t; YAW_ACCEL = 1 deg/t^2
drag     = -(0.02 + 0.01 * |vh|) * vh  horizontally;  -0.05 * vy vertically
up(ψ,θ,φ) = the body up axis: pushing (0,1,0) through Ry(ψ) Rx(θ) Rz(φ) in the mod's convention
           (match HelicopterEntity.rotorAxis so the renderer's quaternion agrees; write the quaternion
           with MathUtil.toQuaternionf(yaw, pitch, roll) using the same signs the helicopter uses)
step(a_extra): v += T/m * up + drag + a_extra - (0, G, 0);  p += v
```

`a_extra` is the rope reaction (below). The entity applies `p`/`v` through `setDeltaMovement` and
`move(MoverType.SELF)` so terrain collision is vanilla's; after `move`, read the position back into `p`
and zero the velocity component vanilla blocked (compare wanted and achieved motion per axis, as
`PlaneCollisions.afterMove` does; a blocked axis with `|v| > 0.3` deals `4 * (|v| - 0.3) * 10` damage to
the drone's 10 HP, cooldown 8 ticks).

### 2. `entities/crane/CraneController` (plain)

Inputs: target position, current `p`, `v`, load mass `m_load`, rope length `L`, load velocity `v_load`.
Outputs: `θ_cmd`, `φ_cmd` (or equivalently a world-frame commanded acceleration), `T`, yaw command.

```
K_POS 0.05; V_MAX 0.8; K_VEL 0.15; A_MAX 0.018 (empty); A_MAX_LOADED = 0.010 * min(1, L / 4)
K_ALT 0.05; VZ_MAX 0.30; K_VZ 0.2
per horizontal axis:  v_cmd  = clamp(K_POS * (target - p), +-V_MAX)
                      v_cmd += k_s * (v_load - v)         with k_s = -0.4 * min(1, m_load / 0.65), only when carrying
                      a_cmd  = clamp(K_VEL * (v_cmd - v), +-A_MAX(loaded?))
vertical:             vz_cmd = clamp(K_ALT * (target_y - y), +-VZ_MAX);  a_z = K_VZ * (vz_cmd - vy)
tilt_cmd = atan2(|a_cmd_h|, G + a_z) clamped to TILT_MAX, in the direction of a_cmd_h (world), converted to
           (θ_cmd, φ_cmd) in the body frame using ψ
T        = clamp(m_total * (G + a_z) / cos(tilt_now), 0, T_MAX)
yaw_cmd  = direction of travel when |v_h| > 0.15, else unchanged
```

The swing term's sign is negative on purpose (the drone accelerates against the load's velocity relative
to itself); the design's simulation found the positive law unstable at every gain and the negative law
killing a 20-degree swing with a cow from 20 to 1.2 deg in 5 s. **Test both signs in T13 and keep the
better one; report the numbers.**

### 3. `entities/crane/SlungLoad` (plain)

```
L in [1.0, 12.0], winch rate 0.15 b/t; winch point (0, 0.30, 0) in the drone's frame (rotated by yaw, it is on the axis so no change)
θx, θz: rope angle from the downward vertical in the x-y and z-y planes; ωx, ωz their rates
per tick, per axis, with a_p = the drone's horizontal acceleration this tick on that axis:
    ω += -(G / L) * sin θ - (a_p / L) * cos θ - 0.002 * ω;   θ += ω
load position  = p_drone + (0, 0.30, 0) + L * (sin θx, -cos(max(|θx|,|θz|)), sin θz)   (the box top of the load sits here)
reaction on the drone (a_extra), per axis: -(m_load / m_total) * (G * cos θ + L * ω^2) * sin θ  horizontally,
                                           and -(m_load / m_total) * G vertically is already inside T (m_total includes the load)
mass: m_load = w^2 * h of the mob's bounding box, clamped >= 0.05;  MAX_LOAD = 1.55
```

Integrate `θ` on the server only; sync `L`, `θx`, `θz` as synched floats (`ROPE_LENGTH`,
`ROPE_THETA_X`, `ROPE_THETA_Z`; replace the foundation's `HOOK_OFFSET` with these) so the client computes
the same load position and the rope end.

### 4. `QuadcopterEntity`

- `getControllingPassenger()` returns null always. `isNoGravity()` false now (the physics applies G).
- `canAddPassenger(e)`: only the entity the state machine has pre-approved (`pendingLoad`), and only one.
- `positionRider(passenger, moveFunction)`: place the passenger so that the **top** of its bounding box
  is at the load position (`y_feet = load_y - passenger.getBbHeight()`), both sides, every tick.
  `getDismountLocationForPassenger` returns the load position (a sneaking player drops from where they
  hang). `shouldRiderSit()` is vanilla's default (players are drawn sitting; accepted).
- Chunk ticket: while not `IDLE` on the ground, `addTicketWithRadius(TicketType.ENDER_PEARL,
  chunkPos, 2)` on the current chunk and the chunk one second ahead along `v`, renewed every 5 ticks
  from `CraneRegistry`'s server-tick hook (same shape as `AutopilotRegistry`/`PlaneAutopilot.keepChunksLoaded`).
- Rotor animation (client): `propellerRotationNew += 0.6 + 4.0 * T / T_MAX` per tick (sync `T` as a
  float `THRUST`).
- Save/load: `state` (name), `target` (3 doubles), `rope_length`, `theta_x`, `theta_z`, `carrying`,
  `owner` (UUID of the remote's holder, optional), `home` (3 doubles, optional), `health`, `material`.
  A saved `carrying` with the passenger restored by vanilla's `Passengers` tag keeps the load; if the
  passenger did not come back, `carrying` is cleared and the jaws open.
- Power: always powered (electric); nothing to fuel.
- Damage: `hurtServer` as the foundation left it; at 0 HP the rotors stop (`T = 0`), it falls, releases
  the load (stopRiding) on the way down, explodes on contact like a plane (`explode` with
  `Blast.DEFAULT` scaled to 1.5 power, no fire, no block damage) and drops nothing.

### 5. State machine (in `QuadcopterEntity`, states as an enum, names saved)

```
IDLE        on the ground or hovering at the last target; jaws open
TO_PICKUP   target = above the load: (x, y_top + 1.5 + 4.0, z) of the chosen entity; V_MAX; when within 0.6 b
            horizontally and 0.8 b vertically for 10 ticks -> LOWER
LOWER       winch out at 0.15/t until the hook (load position with no load) is within 0.6 b of the target's
            box top; the drone holds position and re-targets the mob if it walks (target follows it, up to
            8 b; beyond, abort "target moved away"); 160-tick timeout -> abort
ATTACH      mass check (< = MAX_LOAD, allowed type); target.startRiding(drone, true, true); carrying = true;
            θ = 0 (the rope is vertical when it hooks) -> WINCH_IN.  Refusals: CraneFeedback "too heavy: <name> is
            m.mm, limit 1.55" / "cannot lift <name>" -> IDLE
WINCH_IN    winch to L_CARRY = 3.0 -> CARRY (target = current position but y = ground + 10 + L)
CARRY       flies to the delivery point when one is set: cruise at agl = max(10, obstacle clearance) + L,
            V_MAX 0.8; when within 0.6 b horizontally of the delivery point -> LOWER_LOAD
LOWER_LOAD  descend until the load's box bottom is 0.2 b above the MOTION_BLOCKING surface under it, then
            winch out to keep it there; when the load's bottom is within 0.3 b of the surface for 5 ticks -> RELEASE
RELEASE     passenger.stopRiding(); carrying = false; jaws open -> STOW
STOW        winch to 1.0 -> IDLE (hover at agl 6 over the release point) unless a recall is pending
RETURN      fly to the owner: hover 4 b from the player at agl 3, then land (descend until on the ground) -> IDLE
LAND        descend at 0.15 b/t until onGround -> IDLE
OVERLOAD    entered from any carrying state when T has been saturated for 20 ticks and vy < -0.02:
            if agl < 1.5 -> RELEASE, else winch out toward the ground and then RELEASE; feedback "load released: overweight"
```

Allowed loads: `LivingEntity`, alive, not `Enemy`, not `getType().is(EntityTypeTags.BOSSES)` (use the
vanilla tag if present, else a hard list: ender dragon, wither), not already a passenger or vehicle,
not a `PlaneEntity`/`QuadcopterEntity`, not a spectator; `simpleplanes:crane_never` denies,
`simpleplanes:crane_liftable` overrides the `Enemy` rule; mass `<= 1.55`.

### 6. Remote (`items/CraneRemoteItem`) and feedback

| action | effect |
|---|---|
| `use` while looking at a quadcopter within 6 b | link (`CRANE_LINK` component = entity UUID); "linked to crane #id" |
| `interactLivingEntity` on a mob or player | linked crane -> `TO_PICKUP` on it; "crane #id: picking up <name>" |
| `useOn` a block | carrying: delivery point = top face of that block; else fly there and hover at agl 6 |
| sneak + `use` in the air | `RETURN` to the player |
| sneak + `useOn` a block | `LAND` on that block's top |
| no link, or the crane is not loaded / dead | "no crane linked" / "crane #id is not loaded" |

`crane/CraneFeedback`: `report(owner, message)` sends to the owner's chat if online, and always logs at
`INFO` with the prefix `Crane #id: ...` so `console.log` carries every terminal event (picked up, set
down, refused, released overweight, landed, lost).

### 7. `/crane` command (permission level 2, console-friendly)

| subcommand | effect |
|---|---|
| `spawn <x y z>` | spawns a quadcopter on the ground/at the point, tags it `aircraft-test`, prints `Crane #id spawned` |
| `goto <id> <x y z> [agl]` | target = point (or `agl` above the surface there) |
| `pickup <id> <targets>` | vanilla entity selector; the first match becomes the pickup target |
| `deliver <id> <x y z>` | delivery point |
| `land <id>` | `LAND` |
| `winch <id> <length>` | set `L` (1..12), test aid |
| `status [id]` | `#id state= pos= vel= tilt= thrust= L= thetaX= thetaZ= load=<name or none> mass= sat= agl=` |
| `stop <id>|all` | -> `IDLE`, releases a carried load if it is within 1.5 b of the ground, else lowers it first |
| `trace <id> on|off` | per-tick `trace crane #id t= state= pos= vel= tilt= thrust= L= theta= load= sat=` logged at `INFO`; `-Dsimpleplanes.crane.trace=true` turns it on for all |
| `kill` | removes every crane and every tagged load |
