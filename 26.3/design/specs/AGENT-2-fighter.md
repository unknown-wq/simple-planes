# AGENT-2: the fighter jet (Minecraft 26.3 line)

You implement the flight model of the fighter: a fast, agile single-seat jet, piloted by the player,
with no weapons in scope. The entity, item, model, renderer, registration and the headless test
command already exist on your base branch (built by the foundation agent); you replace the stub
numbers with the design's, add the tail-strike clamp, and prove the numbers on your own test server.
The design is `26.3/design/DESIGN.md` (§1.4, §2, §3, §8.3, §11.1); the plan is `26.3/design/PLAN.md`.
Read the foundation's report `26.3/design/reports/AGENT-1-REPORT.md` first: it says what the harness
actually does.

## Goal

`FighterEntity` flies like a jet. Every quantity is in blocks, ticks and degrees; 20 ticks = 1 s.

### Parameters (override in `FighterEntity`)

| hook / field | value | starter plane |
|---|---|---|
| `pushPerNotch()` | `0.012f` | 0.00625 |
| `MAX_SPEED` entity data (set in the constructor with `setMaxSpeed(2.5f)`) | 2.5 | 1.0 |
| `getMotionVars()`: `maxSpeed` | 3.0 | 3.0 |
| `takeOffSpeed` | 0.45 | 0.30 |
| `stallSpeedFactor` | 0.6 | 0.55 |
| `liftSaturationFactor` | 1.3 | 1.3 |
| `maxLift` | 2.0 | 2.0 |
| `dragQuad`, `dragMul`, `drag` | 0.00145, 0.0005, 0.001 | 0.001, 0.0005, 0.001 |
| `pitchToMotion` | 0.3 | 0.2 |
| `yawToMotion` | 0.2 | 0.1 |
| `motionToRotation` | 0.05 | 0.05 |
| `getRotationSpeedMultiplier()` | 1.4 (pitch ramps 0.7 to 7.0 deg/t, yaw to 3.5) | 1.0 |
| `maxRollRate()` | 8.0 | 5.0 |
| `getGroundPitch()` | 0 | 5 |
| `groundPitchLimit()` | 10.0 | none |
| `groundRollingResistance()` | 0.030 | 0 |
| `groundLinearDragFactor(f)` | 24.0 | 20*(3-f) = 48 on grass |
| `getLandingAngle()` | 30 (inherited) | |
| `minPitchAuthority`, `minGroundSteering` | inherited (0.35, 0.2) | |

`getMotionVars()` is `PlaneEntity`'s: call `super.getMotionVars()` and overwrite the fields
(`TempMotionVars` fields are package-private; `FighterEntity` is in the same package). Keep the
foundation's seat, rider count, item, upgrade filter and camera multiplier.

The tail-strike clamp is already in `PlaneEntity.tickPitch` through `groundPitchLimit()`; the value 10
is 2 degrees under the geometric strike angle (the nozzle bottom sits 0.75 b above the pivot's height
and 3.5 b behind it: `asin(0.75/3.5) = 12.4 deg`).

The nozzle animation needs nothing from you: the foundation copies `throttle / 5` into the render state
and `FighterExhaustModel` reads it. If you add a booster, throttle 6..10 shows the same full afterburner.

### Expected numbers (from the design's simulation of the mod's own tick, DESIGN.md §11.1)

| quantity | design value |
|---|---|
| stall speed | 0.27 b/t |
| ground steady speed at throttle 2 / 3 / 5 | 0.02 / 0.19 / 0.84 b/t |
| level flight speed at throttle 1 / 2 / 3 / 4 / 5 | 1.08 / 1.46 / 1.77 / 2.04 / 2.30 b/t, trim -1.4 to -4.8 deg |
| take-off: rotation / airborne (y0 + 1) | 5.6 b at 20 t / 12.5 b at 32 t, 0.76 b/t |
| climb at 10 / 20 deg nose-up, throttle 5 | 0.485 / 0.75 b/t |
| glide at throttle 0, nose 5 deg down | 0.43 b/t, sink 0.12 b/t |
| unbanked turn, full rudder | nose 3.5 deg/t nominal; track 2.9 deg/t (58 deg/s); radius 20 b at 1.0 b/t |

The rig's yaw model differs from the simulation's in one respect: the autopilot banks into turns, and a
body-frame yaw at bank angle r produces `cos(r)` of the heading rate (`HelicopterEntity.applyYaw`'s
note). Measure the unbanked case (`set roll 0`) for the acceptance table and report the banked case as
information.

## Integration

- Edit only `entities/FighterEntity.java` (and its class javadoc: one paragraph, the parameter table
  above, no essay).
- The foundation's `/aircraft` command drives the tests: `spawn fighter`, `set`, `launch`, `hold`,
  `trim`, `takeoff`, `status`, `trace`, `kill`. If a measurement needs a subcommand that does not
  exist, add it under `/aircraft fighter <...>` with a single registration line in `AircraftCommand`
  and document it.
- `AircraftType.FIGHTER` exists; `/autopilot route ... type fighter` and `inbound`/`flight` will fly
  the fighter with the flight director's stock gains. Not required to be tuned; report how it behaves
  (T9) and, if it oscillates, which `AutopilotConfig` quantity is at fault, without changing it.
